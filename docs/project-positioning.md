# Project Positioning

## Name

**Mercury Method Lab**.

The project is a companion method, evidence, audit, and migration lab for Mercury Agent-compatible workflows.

## Current Version

`0.2.0` — **Open Orbit**.

This version shifts the project from a local V8-only backend toward an upstream-compatible method lab. It keeps the current artifact architecture, but makes room for `cosmicstack-labs/mercury-agent` upgrades and future memory architectures.

## Version Policy

| Segment | Meaning |
| --- | --- |
| Major | Breaks artifact, memory, or upstream compatibility contracts. |
| Minor | Adds a compatible architecture capability, adapter, migration path, or public workflow. |
| Patch | Fixes docs, validation, scripts, or non-breaking metadata. |

## Position

Mercury Method Lab is not a prompt pack. It is not a fork of upstream Mercury Agent. It is not a vendor copy of any third-party skill library.

It owns:

- evidence preservation
- artifact state flow
- method routing
- reviewable memory candidates
- decision and audit trails
- migration envelopes
- public practice guidance

Upstream Mercury Agent owns:

- 24/7 runtime
- CLI and Telegram channels
- permission-hardened tools
- daemon and scheduler
- provider fallback
- runtime Second Brain memory
- installed Agent Skills runtime

## Strategic Boundary

The high-value layer is the artifact and audit operating model:

```text
source -> structure -> fact -> uncertainty -> memory -> decision -> action -> audit -> export -> review
```

This layer should stay independent from any single author, model, skill pack, or runtime implementation.

## dbskill Boundary

`dbskill` can be studied as a public example of skill packaging and creator/business diagnosis demand. It must not become a dependency.

Allowed:

- learn from the general problem space
- identify missing creator, content, and commercial diagnosis capabilities
- rewrite ideas in Mercury Method Lab's own language
- cite public sources when writing public analysis

Forbidden:

- copy skill text
- import atoms or knowledge packages
- inherit naming and routing structure
- make public positioning depend on dbskill
- turn this project into a dbskill derivative

## Competitive Field

Weak positioning:

- another prompt pack
- another personal productivity agent
- another knowledge base wrapper

Stronger positioning:

- local-first method lab for evidence-backed judgment
- auditable memory and decision pipeline
- companion layer for Mercury Agent and future agent runtimes
- bilingual public practice system for reasoning, project judgment, and action translation
